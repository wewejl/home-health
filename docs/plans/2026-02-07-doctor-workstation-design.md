## 一、需求概述

将后端管理系统中医生和工作人员的页面完全分离，为医生创建专属工作台。

### 核心需求

1. **查看患者对话** - 查看患者与 AI 医生助手的咨询对话记录
2. **下达医嘱** - 为患者创建和管理医嘱
3. **查看患者任务完成状态** - 监控患者对医嘱的执行情况

### 设计决策

| 决策点 | 选择 | 说明 |
|--------|------|------|
| 用户系统 | 完全独立 | 创建独立的医生表和工作人员表 |
| 前端入口 | 完全分离 | `/doctor/*` 和 `/admin/*` 完全隔离 |
| 对话类型 | AI 咨询对话 | 患者与 AI 医生助手的对话记录 |
| 任务展示 | 患者详情模式 | 以患者为中心，点击进入查看任务 |

#### 关键发现

1. **`doctors` 表已存在** - 设计方案中提到的"新建 doctors 表"实际上已存在，无需创建
2. **医嘱数据模型完备** - `medical_orders` 表已有 `doctor_id` 字段关联到 `admin_users`
3. **对话数据可获取** - `sessions` 表有 `doctor_id`，可按医生筛选患者的对话

### 11.2 需要调整的设计

#### 原设计问题
```sql
-- 方案中设计的 doctors 表（与现有表重复）
CREATE TABLE doctors (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,  -- ❌ 现有表没有 username
    password_hash VARCHAR(255) NOT NULL,   -- ❌ 现有表没有密码字段
    ...
);
```

#### 调整方案
现有 `doctors` 表**不包含登录信息**，需要两种方案：

| 方案 | 描述 | 优缺点 |
|------|------|--------|
| **A: 扩展 doctors 表** | 添加 username/password_hash 字段 | ✅ 简单直接<br>❌ 需要迁移 |
| **B: 复用 admin_users** | 在 admin_users 添加 role='doctor' | ✅ 无需新建表<br>❌ 语义不清晰 |

**推荐：方案A** - 扩展 doctors 表，保持医生用户的独立性。

## 十二、风险评估与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| doctors 表迁移影响现有功能 | 中 | 做好数据备份，分步迁移 |
| 医生权限与 admin 权限冲突 | 低 | 使用独立的 JWT token 和前缀 |
| 前端代码复用导致耦合 | 中 | 抽取共享组件到 `components/` 目录 |
| 对话记录量大导致性能问题 | 中 | 实现分页和按日期筛选 |
