# 科室智能体代码分析报告

## 1. 概述

### 1.1 系统简介

心灵医生项目的科室智能体系统是一个基于 **ReAct（Reasoning + Acting）架构**的多智能体医疗问诊系统。系统采用 LangGraph 框架构建状态图，通过 AI 自主决策实现问诊流程，无需硬编码规则。

### 1.2 技术栈

| 组件 | 技术 |
|------|------|
| 智能体框架 | LangGraph 1.x |
| 大语言模型 | 通义千问 (Qwen) |
| 后端框架 | FastAPI |
| 数据库 | PostgreSQL (通过 SQLAlchemy ORM) |
| 状态管理 | LangGraph StateGraph + JSON 序列化 |

### 1.3 主要功能

- **多科室智能体路由**：支持 13 个医疗科室的智能体
- **自主问诊决策**：AI 根据收集的信息自主决定下一步操作
- **工具调用**：支持医学知识查询、图像分析、风险评估等工具
- **流式响应**：支持 SSE 流式输出
- **状态持久化**：会话状态保存到数据库，支持断点续诊

### 3.2 智能体调用链路

```
用户发送消息
    ↓
1. 解析请求 (sessions_v2.py:84-134)
   - 获取会话
   - 验证用户权限
   - 确定智能体类型
    ↓
2. 获取智能体实例 (AgentRouterV2.get_agent)
   - 根据 agent_type 从注册表获取
   - 创建智能体实例
    ↓
3. 恢复会话状态
   - 从数据库读取 agent_state
   - 反序列化为字典
    ↓
4. 运行智能体 (agent.run)
   - 执行 LangGraph 状态图
    ↓
5. ReAct 循环 (react_base.py)
   ┌─────────────────────────────────────┐
   │  reasoning_node (推理节点)           │
   │  - 分析当前状态                      │
   │  - 决定：使用工具 / 直接回复 / 结束  │
   └──────────────┬──────────────────────┘
                  │
         ┌────────┴────────┐
         ↓                 ↓
   tool_executor_node   response_generator_node
   (工具执行节点)        (响应生成节点)
         │                 │
         └────────┬────────┘
                  ↓
    返回 AgentResponse
    ↓
6. 保存状态到数据库
   - 序列化状态
   - 保存消息记录
   - 更新会话状态
    ↓
7. 返回响应给客户端
   - SSE 流式或 JSON
```

### 3.3 数据流向

```
用户输入 (content + attachments)
    ↓
┌──────────────────────────────────────────────┐
│ Message 模型 (数据库记录)                     │
│ - sender: user                               │
│ - content: 用户消息内容                       │
│ - attachments: 附件数据                       │
└──────────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────────┐
│ AgentState (智能体状态)                       │
│ - messages: 对话历史                          │
│ - medical_context: 医学上下文                 │
│ - stage: 当前阶段                             │
│ - progress: 进度                              │
└──────────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────────┐
│ ReAct 循环处理                                │
│ 1. reasoning: AI 分析状态并决策               │
│ 2. tool_executor: 执行工具（如需要）          │
│ 3. response_generator: 生成回复               │
└──────────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────────┐
│ AgentResponse (统一响应格式)                  │
│ - message: AI 回复内容                        │
│ - stage: 当前阶段                             │

│ - specialty_data: 专科数据                    │
│ - next_state: 下一轮状态                      │
└──────────────────────────────────────────────┘
    ↓
保存到数据库 (Message + Session.agent_state)
    ↓
返回给客户端 (SSE 流式 / JSON)
```

### 4.1 科室路由机制

**科室名称 → 智能体类型映射** (`router.py:56-132`):

```python
_DEPARTMENT_MAPPING = {
    # 皮肤科
    "皮肤": "dermatology",
    "皮肤科": "dermatology",
    "皮肤性病": "dermatology",

    # 心血管科
    "心内": "cardiology",
    "心内科": "cardiology",
    "心血管": "cardiology",

    # 骨科
    "骨科": "orthopedics",

    # ... 其他科室
}

def infer_agent_type(department_name: str) -> str:
    """根据科室名称推断智能体类型"""
    # 支持模糊匹配和关键词匹配
    if department_name in mapping:
        return mapping[department_name]
    for keyword, agent_type in mapping.items():
        if keyword in department_name:
            return agent_type
    return "general"
```

### 4.2 不同科室的差异处理

| 差异维度 | 实现方式 |
|----------|----------|
| **系统提示词** | 每个智能体实现 `get_system_prompt()` 返回科室特定提示词 |
| **可用工具** | 每个智能体实现 `get_tools()` 返回工具列表 |
| **能力配置** | 每个智能体实现 `get_capabilities()` 返回能力描述 |
| **专科状态** | 子类可扩展 `medical_context` 添加科室特有字段 |

## 6. 代码质量评估

### 6.1 优点

| 维度 | 描述 |
|------|------|
| **架构清晰** | 采用 ReAct 模式，AI 自主决策，减少硬编码规则 |
| **模块化良好** | 基类定义接口，子类实现特化逻辑，扩展新科室简单 |
| **统一响应格式** | `AgentResponse` 提供一致的数据结构 |
| **流式支持** | 支持 SSE 流式输出，提升用户体验 |
| **状态持久化** | 会话状态保存到数据库，支持断点续诊 |
| **并行工具执行** | 支持同时执行多个独立工具，提升性能 (`react_base.py:481-488`) |

### 6.2 缺点

| 维度 | 描述 | 位置 |
|------|------|------|
| **架构不统一** | 存在两套路由系统 (`AgentRouter` vs `AgentRouterV2`) | `router.py` vs `agent_router_v2.py` |
| **V2 版本未完成** | `AgentRouterV2` 只注册了 2 个智能体，其余 11 个未迁移 | `agent_router_v2.py:17-21` |
| **重复代码** | `sessions.py` 和 `sessions_v2.py` 有大量重复逻辑 | 路由层 |
| **错误处理不足** | 部分异常捕获后只返回通用错误消息 | `react_base.py:260-265` |
| **缺少测试** | 未发现针对智能体的单元测试 | - |
| **调试日志过多** | 代码中存在大量 `print` 调试语句 | 多处 |
| **状态序列化复杂** | 需要手动处理 LangChain Message 对象 | `react_base.py:1090-1152` |
| **工具注册硬编码** | 工具 Schema 需要手动维护 | `tools/__init__.py` |

### 6.3 改进建议

| 优先级 | 建议 | 预期效果 |
|--------|------|----------|
| **高** | 统一架构，完成 V2 智能体迁移 | 消除重复代码，简化维护 |
| **高** | 添加单元测试和集成测试 | 提高代码质量和可维护性 |
| **中** | 替换 `print` 为标准 logging 库 | 更好的日志管理 |
| **中** | 简化状态序列化逻辑 | 减少潜在错误 |
| **中** | 改进错误处理，添加详细错误码 | 更好的问题定位 |
| **低** | 自动生成工具 Schema | 减少手动维护 |

#### ReAct 状态图构建 (`react_base.py:162-192`)

```python
def _build_graph(self) -> StateGraph:
    """构建 ReAct 状态图"""
    graph = StateGraph(ReActAgentState)

    # 添加节点
    graph.add_node("reasoning", self._reasoning_node)
    graph.add_node("tool_executor", self._tool_executor_node)
    graph.add_node("response_generator", self._response_generator_node)

    # 设置入口
    graph.set_entry_point("reasoning")

    # 条件边：根据 AI 决策路由
    graph.add_conditional_edges(
        "reasoning",
        self._route_decision,
        {
            "use_tool": "tool_executor",
            "respond": "response_generator",
            "diagnose": "response_generator",
            "end": END,
        }
    )

    # 工具执行后回到推理
    graph.add_edge("tool_executor", "reasoning")

    # 响应生成后结束
    graph.add_edge("response_generator", END)

    return graph.compile()
```

## 8. 总结

### 8.1 核心设计原则

1. **AI 自主决策**：使用 ReAct 模式，AI 根据上下文自主决定操作，减少硬编码规则
2. **模块化扩展**：新增科室只需实现 3 个方法（`get_system_prompt`, `get_tools`, `get_capabilities`）
3. **统一数据流**：所有智能体返回统一的 `AgentResponse` 格式
4. **状态持久化**：支持断点续诊，状态保存在数据库中

### 8.2 架构演进

```
V1: CrewAI 架构 → V2: LangGraph + ReAct → 未来: AgentRouterV2 (未完成)
```

当前生产环境使用 **V2 (LangGraph + ReAct)** 架构，支持 13 个科室智能体。

### 8.3 技术亮点

- **LangGraph 状态图**：可视化、可调试的智能体流程
- **并行工具执行**：提升响应速度
- **SSE 流式输出**：更好的用户体验
- **学科专业化**：每个科室有独立的系统提示词和工具集
