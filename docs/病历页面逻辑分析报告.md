## 二、详细问题分析与评审

### 问题 1: 科室类型命名不一致 ⚠️ [已确认]

**严重程度**: 高

**位置**:
- iOS: `DepartmentType` 枚举 (MedicalDossierModels.swift:5-27)
- 后端: `AgentType` 枚举 (medical_event.py:28-37)

**问题描述**:

iOS 和后端使用不同的命名约定，导致类型映射问题：

| 科室 | iOS 枚举值 | 后端枚举值 | API 返回值 | 匹配? |
|------|------------|------------|------------|-------|
| 皮肤科 | `dermatology` | `derma` | `derma` | ❌ |
| 心内科 | `cardiology` | `cardio` | `cardio` | ❌ |
| 骨科 | `orthopedics` | `ortho` | `ortho` | ❌ |
| 神经科 | `neurology` | `neuro` | `neuro` | ❌ |
| 消化科 | `gastroenterology` | `gastro` | `gastro` | ❌ |
| 全科 | `general` | `general` | `general` | ✅ |

**代码证据**:

```swift
// MedicalDossierModels.swift:5-27
enum DepartmentType: String, Codable {
    case dermatology = "dermatology"  // ❌ 后端返回 "derma"
    case cardiology = "cardiology"    // ❌ 后端返回 "cardio"
    case general = "general"          // ✅ 匹配
    // ...
}
```

```swift
// MedicalEventAPIService.swift:297
department: DepartmentType(rawValue: agent_type) ?? .general,
// 当 agent_type = "derma" 时，rawValue 解析失败，返回 .general
```

**实际影响**:
- ❌ 所有皮肤科、心内科等专科事件都被错误识别为"全科"
- ❌ 图标、颜色显示错误
- ❌ 筛选功能失效

**修复建议**:
修改 iOS `DepartmentType` 枚举值匹配后端，或添加自定义 `init(from decoder)` 处理映射。

### 问题 2: 事件状态枚举不完整 ⚠️ [已确认]

**严重程度**: 高

**位置**:
- iOS: `EventStatus` 枚举 (MedicalDossierModels.swift:91-114)
- 后端: `EventStatus` 枚举 (medical_event.py:12-17)

**问题描述**:

```swift
// iOS 定义
enum EventStatus: String, Codable {
    case inProgress = "in_progress"  // ❌ 后端不返回这个值
    case completed = "completed"
    case exported = "exported"
    case archived = "archived"
    // ❌ 缺少: active
}
```

```python
# 后端定义 (medical_event.py:12-17)
class EventStatus(str, enum.Enum):
    active = "active"      # ✅ 默认状态
    completed = "completed"
    exported = "exported"
    archived = "archived"
```

**代码证据**:

```swift
// MedicalEventAPIService.swift:298
status: EventStatus(rawValue: status) ?? .inProgress,
// 当 status = "active" 时，解析失败，fallback 到 .inProgress
```

**实际影响**:
- 后端默认返回 `status: "active"` 的事件
- iOS 无法解析，使用 fallback 值 `.inProgress`
- 但 iOS 筛选条件 `inProgress` 转换成 API 参数 `status=in_progress`，后端不识别
- 导致**无法正确筛选活跃事件**

**修复建议**:
在 iOS `EventStatus` 中添加 `case active = "active"`，并调整筛选逻辑。

### 问题 4: 筛选逻辑缺陷 ⚠️ [前端筛选，不影响后端]

**严重程度**: 低

**位置**: MedicalDossierViewModel.swift:68-93

**原报告分析**: 原报告认为筛选选项不完整导致功能缺失。

**评审发现**:
iOS 端的筛选是**客户端本地筛选**，不传递给后端 API：

```swift
// MedicalDossierViewModel.swift:101-115
private func loadEvents() async {
    // ...
    let response = try await MedicalEventAPIService.shared.fetchEvents()
    // ✅ 获取全部数据，然后在本地筛选
    events = response.events.map { $0.toMedicalEvent() }
    applyFilters(searchText: searchText, filter: selectedFilter)
}
```

```swift
// MedicalEventAPIService.swift:132-147
func fetchEvents(
    page: Int = 1,
    pageSize: Int = 20,
    status: String? = nil,  // ⚠️ 有参数但未在筛选逻辑中使用
    department: String? = nil
)
```

**实际影响**:
- ✅ 前端筛选对当前显示的数据有效
- ⚠️ 但当数据量超过分页大小时，筛选结果不完整
- ⚠️ 问题2 的状态解析问题会影响筛选结果

**修复建议**:
将筛选参数传递给后端 API，或在数据量大时使用服务端筛选。

## 四、修复优先级与方案

### 🔴 优先级 P0 - 立即修复

#### 4.1 修复科室类型映射

**方案**: 在 `DepartmentType` 添加自定义解码

```swift
extension DepartmentType {
    init(from decoder: Decoder) throws {
        let container = try decoder.singleValueContainer()
        let rawValue = try container.decode(String.self)

        // 映射表
        let mapping: [String: DepartmentType] = [
            "derma": .dermatology,
            "cardio": .cardiology,
            "ortho": .orthopedics,
            "neuro": .neurology,
            "gastro": .gastroenterology,
            "general": .general
        ]

        self = mapping[rawValue] ?? .general
    }
}
```

## 六、方案C：重构数据模型 - 统一映射层设计

### 6.1 架构概述

创建一个统一的 `BackendMapper` 层，作为前端数据模型和后端API响应之间的转换层。这个mapper负责：

1. **类型安全转换**：将后端返回的字符串枚举值（如 `derma`）转换为前端枚举（如 `dermatology`）
2. **容错处理**：当后端返回未知值时提供合理的fallback
3. **数据补全**：处理缺失字段（如messages数组）

#### 目录结构

```
ios/xinlingyisheng/xinlingyisheng/
├── Services/
│   ├── Mapping/
│   │   ├── BackendMapper.swift           # 统一映射入口
│   │   ├── DepartmentMapping.swift       # 科室映射
│   │   ├── EventStatusMapping.swift      # 状态映射
│   │   └── MedicalEventMapping.swift     # 事件映射
```

#### 设计优势

3. **易于维护**：当后端API变化时，只需修改mapper
4. **类型安全**：编译时检查，避免运行时错误

/// 生成时间线项（支持按需加载）
func generateTimelineItems(for event: MedicalEvent) async -> [TimelineItem] {
    var items: [TimelineItem] = []

    // 添加事件创建时间点
    items.append(TimelineItem(
        id: "event-\(event.id)",
        date: event.startDate,
        title: "创建病历",
        description: event.summary ?? "无摘要",
        icon: "folder.badge.plus",
        color: event.department.color
    ))

    // 添加会话时间点
    for session in event.sessions {
        let item = TimelineItem(
            id: "session-\(session.sessionId)",
            date: session.startTime,
            title: "咨询记录",
            description: session.summary ?? "暂无摘要",
            icon: "bubble.left.fill",
            color: .blue
        )
        items.append(item)

        // 如果有消息，添加消息时间点
        if !session.messages.isEmpty {
            for message in session.messages {
                items.append(TimelineItem(
                    id: "message-\(message.id)",
                    date: message.timestamp,
                    title: message.isUser ? "用户消息" : "医生回复",
                    description: message.text,
                    icon: message.isUser ? "person.fill" : "text.bubble.fill",
                    color: message.isUser ? .green : .blue
                ))
            }
        }
    }

    // 添加附件时间点
    for attachment in event.attachments {
        items.append(TimelineItem(
            id: "attachment-\(attachment.id)",
            date: attachment.createdAt,
            title: "添加附件",
            description: attachment.fileName,
            icon: "paperclip",
            color: .orange
        ))
    }

    // 添加笔记时间点
    for note in event.notes {
        items.append(TimelineItem(
            id: "note-\(note.id)",
            date: note.createdAt,
            title: "添加笔记",
            description: note.content,
            icon: "note.text",
            color: .purple
        ))
    }

    return items.sorted { $0.date > $1.date }
}
