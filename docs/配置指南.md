# 配置指南

## 概述

本项目使用环境变量进行配置管理，配置文件位于 `backend/.env`。配置类定义在 `backend/app/config.py`。

### 配置文件加载顺序

1. `.env.local` - 本地覆盖配置（不提交到 Git）
2. `.env` - 项目默认配置（提交到 Git）

---

## 环境变量配置

### 应用配置

```env
# 应用名称
APP_NAME=鑫琳医生 API

# 应用版本
APP_VERSION=1.0.0

# 调试模式
DEBUG=true

# 是否生成种子数据
SEED_DATA=true

# 服务端口（固定 8100）
PORT=8100
```

| 配置项 | 说明 | 默认值 | 备注 |
|--------|------|--------|------|
| `APP_NAME` | 应用名称 | 鑆琳医生 API | - |
| `APP_VERSION` | 应用版本 | 1.0.0 | - |
| `DEBUG` | 调试模式 | true | 生产环境设为 false |
| `SEED_DATA` | 生成种子数据 | true | 首次启动设为 true |
| `PORT` | 服务端口 | 8100 | 固定端口 |

### 数据库配置

```env
# PostgreSQL 数据库连接（推荐）
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5433/home_health

# 知识库 SQLite（可选）
KNOWLEDGE_DB_URL=sqlite:///./knowledge.db
```

| 配置项 | 说明 | 默认值 | 备注 |
|--------|------|--------|------|
| `DATABASE_URL` | 主数据库连接 | PostgreSQL | Docker 容器端口 5433 |
| `KNOWLEDGE_DB_URL` | 知识库连接 | SQLite | 用于知识库存储 |

**PostgreSQL 连接格式：**
```
postgresql+psycopg://[用户名]:[密码]@[主机]:[端口]/[数据库名]
```

**数据库启动命令：**
```bash
# 启动 Docker 容器
docker start home_health_db

# 或使用 docker-compose
docker-compose up -d postgres
```

### JWT 认证配置

```env
# JWT 密钥（用户端）
JWT_SECRET_KEY=xinlin-doctor-secret-key-2024

# JWT 算法
JWT_ALGORITHM=HS256

# Access Token 有效期（分钟）
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=480

# Refresh Token 有效期（天）
JWT_REFRESH_TOKEN_EXPIRE_DAYS=7

# 管理员 JWT 密钥
ADMIN_JWT_SECRET=admin-secret-key-change-in-production

# 管理员 Token 有效期（小时）
ADMIN_JWT_EXPIRE_HOURS=24
```

| 配置项 | 说明 | 默认值 | 备注 |
|--------|------|--------|------|
| `JWT_SECRET_KEY` | 用户 JWT 密钥 | - | **生产环境必须修改** |
| `JWT_ALGORITHM` | 加密算法 | HS256 | - |
| `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` | Token 有效期 | 480 | 8 小时 |
| `JWT_REFRESH_TOKEN_EXPIRE_DAYS` | 刷新 Token 有效期 | 7 | 7 天 |
| `ADMIN_JWT_SECRET` | 管理员 JWT 密钥 | - | **生产环境必须修改** |
| `ADMIN_JWT_EXPIRE_HOURS` | 管理员 Token 有效期 | 24 | 24 小时 |

### LLM 配置

```env
# LLM 提供商
LLM_PROVIDER=qwen

# LLM 模型
LLM_MODEL=qwen-plus

# LLM API 地址
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# LLM API Key
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx

# LLM 温度参数
LLM_TEMPERATURE=0.7

# Qwen 多模态模型（皮肤科使用）
QWEN_VL_MODEL=qwen3-vl-plus

# LangGraph 配置
USE_LANGGRAPH=true
LLM_TIMEOUT=30
LLM_MAX_RETRIES=1
LLM_MAX_TOKENS=1500
LLM_VL_MAX_TOKENS=2000
```

| 配置项 | 说明 | 默认值 | 备注 |
|--------|------|--------|------|
| `LLM_PROVIDER` | LLM 提供商 | qwen | 支持 qwen 等 |
| `LLM_MODEL` | 模型名称 | qwen-plus | 可选 qwen-turbo, qwen-max 等 |
| `LLM_BASE_URL` | API 地址 | - | 兼容 OpenAI 格式 |
| `LLM_API_KEY` | API 密钥 | - | **必须配置** |
| `LLM_TEMPERATURE` | 温度参数 | 0.7 | 0-1 之间，越高越随机 |
| `QWEN_VL_MODEL` | 多模态模型 | qwen3-vl-plus | 用于图像分析 |
| `USE_LANGGRAPH` | 使用 LangGraph | true | 智能体框架开关 |
| `LLM_TIMEOUT` | 超时时间（秒） | 30 | LLM 调用超时 |
| `LLM_MAX_RETRIES` | 最大重试次数 | 1 | 失败重试 |
| `LLM_MAX_TOKENS` | 最大 Token 数 | 1500 | 普通模型 |
| `LLM_VL_MAX_TOKENS` | 多模态 Token 数 | 2000 | 图像模型 |

**支持的 LLM 模型：**
- `qwen-turbo` - 通义千问 Turbo（快速）
- `qwen-plus` - 通义千问 Plus（均衡）
- `qwen-max` - 通义千问 Max（强大）
- `qwen3-vl-plus` - 通义千问 VL（多模态）
- `qwen-vl-max` - 通义千问 VL Max

## 密钥获取指南

### 通义千问 API Key

1. 访问 [阿里云百炼平台](https://bailian.console.aliyun.com/)
2. 登录阿里云账号
3. 进入「模型-滑块-模型广场」
4. 创建 API Key
5. 复制 API Key 到 `LLM_API_KEY`

### 智谱 GLM API Key

1. 访问 [智谱 AI 开放平台](https://open.bigmodel.cn/)
2. 注册/登录账号
3. 进入「API Key 管理」
4. 创建新的 API Key
5. 复制 API Key 到 `GLM_API_KEY`

### 阿里云短信服务

1. 访问 [阿里云短信服务](https://dysms.console.aliyun.com/)
2. 开通短信服务
3. 创建签名和模板（需审核）
4. 创建 AccessKey
5. 配置以下环境变量：
   - `SMS_ACCESS_KEY_ID`
   - `SMS_ACCESS_KEY_SECRET`
   - `SMS_SIGN_NAME`
   - `SMS_TEMPLATE_CODE`

## 常见问题

### Q: 修改配置后不生效？

A: 重启后端服务：
```bash
pkill -f "start_server.py"
cd backend
./venv/bin/python start_server.py
```

### Q: 数据库连接失败？

A: 检查 PostgreSQL 容器状态：
```bash
docker ps | grep home_health_db
docker start home_health_db
```

### Q: LLM 调用失败？

A: 检查 API Key 配置：
1. 确认 `LLM_API_KEY` 已正确设置
2. 确认 API Key 有效且未过期
3. 检查网络连接

### Q: 短信发送失败？

A: 检查短信服务配置：
1. 开发环境使用 `SMS_PROVIDER=mock` 只记录日志
2. 生产环境需要配置完整的阿里云参数
3. 确认签名和模板已通过审核

### Q: CORS 跨域问题？

A: 配置 `CORS_ALLOWED_ORIGINS`：
```env
CORS_ALLOWED_ORIGINS=http://localhost:5173,https://yourdomain.com
```

## 安全建议

### 必须修改的配置

生产环境部署前，必须修改以下配置：

1. **JWT 密钥** - 使用强随机密钥
2. **数据库密码** - 使用强密码
3. **CORS 配置** - 明确配置允许的域名

### 生成强密钥

```bash
# 生成随机密钥
python -c "import secrets; print(secrets.token_urlsafe(32))"

# 或使用 openssl
openssl rand -base64 32
```

### 环境变量保护

1. 不要将 `.env` 提交到 Git
2. 使用 `.env.local` 存储本地配置
3. 生产环境使用密钥管理服务

## 核心哲学

### 1. Test-Driven Development (TDD) - 测试驱动开发

```
┌─────────────────────────────────────────────────────────┐
│                    RED-GREEN-REFACTOR                   │
├─────────────────────────────────────────────────────────┤
│  1. RED   - 写一个失败的测试                            │
│  2. GREEN - 写最少的代码让测试通过                      │
│  3. REFACTOR - 重构代码，保持测试通过                    │
└─────────────────────────────────────────────────────────┘
```

**强制规则**：
- ✅ 新功能开发前必须先写测试
- ✅ Bug 修复前先写失败测试用例
- ✅ 提交代码时测试必须通过

### 2. Systematic over Ad-hoc - 系统化而非临时

| ❌ 错误做法 | ✅ 正确做法 |
|------------|------------|
| 直接猜测问题 | 使用 systematic-debugging 流程 |
| 凭感觉修改代码 | 基于证据分析 |
| 无计划写代码 | 先写计划 (writing-plans) |

### 3. Evidence over Claims - 证据优于声明

- ❌ "应该可以工作"
- ✅ "已验证，测试通过"

## 开发流程

### 阶段 1: 需求分析

```
需求明确 → brainstorming (苏格拉底式提问)
     ↓
设计方案 → writing-plans (详细实现计划)
```

### 阶段 2: 实现

```
先写测试 → test-driven-development (RED-GREEN-REFACTOR)
     ↓
编写代码 → 按计划实现
```

### 阶段 3: 调试 (如遇问题)

```
收集症状 → systematic-debugging (4阶段根因分析)
     ↓
定位原因 → 验证修复 → 防御性检查
```

### 阶段 4: 完成验证

```
代码审查 → requesting-code-review
     ↓
实际验证 → verification-before-completion
```

## 项目特定规范

### 后端

| 规范 | 说明 |
|------|------|
| **路由定义顺序** | 固定路径必须在参数化路径之前 (教训：`/patients/assign` 在 `/patients/{id}` 之前) |
| **分层架构** | routes → services → models |
| **错误处理** | 统一使用 HTTPException |
| **数据验证** | 使用 Pydantic schemas |
| **运行环境** | Docker 容器内执行，非本地 venv |

### 前端

| 规范 | 说明 |
|------|------|
| **组件结构** | pages → layouts → components |
| **状态管理** | 使用 Zustand |
| **API 调用** | 统一封装在 `api/index.ts` |
| **类型定义** | TypeScript 接口定义 |

### iOS

| 规范 | 说明 |
|------|------|
| **架构模式** | MVVM |
| **文件大小** | 单文件不超过 500 行 (HomeView 1094 行需拆分) |
| **主题系统** | 使用统一的 HealingColors/UnifiedFont |
| **调试日志** | 生产环境需条件化，避免大量 print |

## 常见陷阱 (Anti-patterns)

| 陷阱 | 后果 | 避免方法 |
|------|------|----------|
| 跳过测试直接写代码 | 质量不稳定 | 使用 TDD |
| 猜测问题原因 | 浪费时间 | systematic-debugging |
| 不验证就声明完成 | 返工 | verification-before-completion |
| 路由顺序错误 | 404 无法匹配 | 固定路径在前 |
| 过度设计 | 复杂度增加 | simplicity-first |

## 文档同步规则

**原则**: 代码修复完成后，必须同步更新相关文档

| 步骤 | 检查项 |
|------|--------|
| 1️⃣ 代码修复 | 修改代码，验证通过 |
| 2️⃣ 更新文档 | 移到"已完成"或"已还清"区域 |
| 3️⃣ 任务完成 | ✅ 代码 + ✅ 文档 都更新了才算完成 |

**禁止**：
- ❌ 代码修复完成，但文档不更新
- ❌ 创建专门的"更新文档"任务
- ❌ 代码修改完成后不更新规划文档
